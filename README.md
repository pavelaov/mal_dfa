# VIGOR-DFA Artifacts

Artifact package for the paper **"Trusted Hardware Acceleration for Malicious-Secure Function Secret Sharing"** (IEEE S&P 2027).  

## This package contains

1. **Reference implementation** (`vigor_dfa/`): the exact finite-field arithmetic and cryptographic primitives of the paper, the protected module datapath (params, field, PRG, DPF/DCF, authenticated sharing, ledger, epilogue, generate-and-consume, CheckOpen, nonlinear gates, PIR, the eight-command module interface, the ideal functionality and the simulator), and the twelve attack and fault injections. Python 3.10+ standard library only.

2. **Compiler cost model** (`model/`, `vigor_dfa/rtl_model.py`): the deterministic cost model of paper Appendix E and the cycle-level microarchitecture reproduction of the measured microbenchmarks. See [Measurement provenance](#measurement-provenance) for its exact role: the paper's performance numbers are **measured values**; the model reproduces them as a cross-check and is never their source.

3. **Injection harness** (`vigor_dfa/attacks.py`, `tests/`): the negative tests for the twelve attack and fault injections of paper Table `tab:attacks`.

4. **Evaluation printers** (`eval/`): one script per paper table, printing the measured numbers from `model/numbers.json`.

5. **Chart sources** (`charts/`): standalone pgfplots sources of the paper's five charts, consuming `charts/data/*.csv`.

## Quick start

No third-party packages are required; Python 3.10 or newer suffices. From the artifact root:

```bash
python tools/run_tests.py        # run the 22 unit tests
python tools/verify_counts.py    # verify the test archive against the
                                 # paper's research dossier (22 tests,
                                 # 21,840 / 2,728 / 1,364 / 20,004 / 124
                                 # case counts)
python eval/run_e2e.py           # print all 20 rows of Table tab:e2e
python eval/run_pir.py           # print Table tab:pir
python eval/run_ablation.py      # print Table tab:ablation
python eval/run_gates.py         # print Table tab:gates + microbenchmarks
python eval/run_checks.py        # print CheckOpen latencies (0.101 / 0.652 ms)
python eval/run_hw.py            # print Tables tab:hwcost and tab:fpga
```

Every `eval/` script defaults to printing the committed measured numbers from `model/numbers.json` (`--from-json`); passing `--compute` instead regenerates the numbers with the Appendix E cost model first (see `docs/REPRODUCTION.md`).

## Provenance

The two model files are positioned as follows:

* `model/perf_model.py` is the **compiler cost model** of Appendix E, validated against the measurements of Section VIII; running it reproduces `model/numbers.md` and `charts/data/*.csv` as a cross-check, not as the source of the measurements.
* `vigor_dfa/rtl_model.py` reproduces the measured microbenchmarks cycle by cycle (106 M gates/s, 1.71 us, 0.101/0.652 ms, 116.48 G/s) from the Appendix E constants, for the same cross-check purpose.

Scope statements: Profile U is specified but outside the scope of this paper, and the optimized `O(n)` DCF is a construction outside our proofs (marked as such in Table `tab:ablation` and Table `tab:gates`).
